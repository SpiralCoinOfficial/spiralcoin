# Governance

## Consensus & Network Changes

- Consensus parameter changes (e.g., block time, difficulty) are proposed via RFCs and require multi-party review.
- Network upgrades are coordinated with node operators through scheduled activation heights.

## Decision Making

- Technical: Maintainers vote after review (lazy consensus). Security fixes may be fast-tracked.
- Non-technical: Community proposals discussed in public channels; outcomes summarized and recorded.

## Versioning & Releases

- Semantic versioning for releases. Release notes include changes, checksums, and upgrade guidance.
